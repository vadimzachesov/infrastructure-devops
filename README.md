# infrastructure-devops
# Фундамент DevOps-инфраструктуры

Репозиторий содержит реализацию сквозного проекта по автоматизации настройки хоста, декларативному управлению ресурсами Docker через Terraform, развертыванию мультиконтейнерного стека на базе Docker Compose и мониторингу состояния сервисов с помощью отказоустойчивого Bash-скрипта.

---

## Архитектурные решения

### 1. Порядок автоматизации (Ansible -> Terraform)
* **Ansible (`ansible/setup_host.yml`) выполняется первым:** на чистой виртуальной машине создается непривилегированный пользователь `deployer` с беспарольным `sudo`.
* В рамках Ansible устанавливаются Docker Engine и плагин Docker Compose, настраивается автозапуск демона `docker.service`.
* **Terraform (`terraform/main.tf`) выполняется вторым:** провайдер `kreuzwerker/docker` подключается к уже функционирующему демону Docker на хосте для декларативного создания инфраструктурных объектов.

### 2. Инфраструктура IaC (Terraform)
* Через Terraform созданы три типа Docker-объектов: пользовательская bridge-сеть `custom_net`, постоянный том `nginx_volume` и контейнер `nginx-container` (`docker_container.web`).
* Контейнер привязан к нестандартному внешнему порту `8080` (`8080:80`) и изолирован в сети `custom-net`.
* При обращении по HTTP контейнер возвращает стандартный ответ `200 OK` от Nginx.

### 3. Прикладной стек (Docker Compose в `/opt/app`)
* В директории `/opt/app` развернут изолированный стек из двух сервисов:
  * `nginx`: обратный прокси-сервер (Reverse Proxy), слушающий стандартный порт хоста `80` (`80:80`) и перенаправляющий входящий трафик во внутреннюю сеть.
  * `app`: контейнер `nginx:alpine`, отдающий статическую страницу `Hello World` через директиву `expose: 80` (без публикации порта на хосте).
* Сервисы взаимодействуют внутри собственной выделенной сети `app-net`.

### 4. Сетевая изоляция (Network Segmentation)
* Сеть Terraform `custom-net` и сеть Compose `app-net` полностью развязаны на уровне ядра Linux.
* Это исключает несанкционированный доступ контейнеров Compose к контейнеру Terraform.

### 5. Мониторинг и надежность (`scripts/monitor.sh`)
* Скрипт использует строгий режим исполнения `set -Eeuo pipefail` для предотвращения скрытых сбоев при конвейерной обработке.
* Реализованы обработчики сигналов `trap`:
  * Функция `cleanup` на псевдосигнал `EXIT` гарантирует удаление временных файлов при любом сценарии завершения.
  * Функция `rollback` на сигналы `ERR`, `INT`, `TERM` фиксирует номер аварийной строки и очищает неконсистентные данные.
* Проверка активности процесса выполняется через `systemctl is-active <service>`.
* При сбое демона извлекаются последние 10 строк журнала службы через `journalctl -u <service> -n 10`.
* Подсчет критических событий в `/var/log/syslog` за последний час реализован через связку `grep` и `awk`.

## Инструкция по развертыванию с нуля

### Предварительные требования
* Локально установленные утилиты: `ansible`, `terraform` (>= 1.5.0), `git`, `ssh`.
* Настроенный доступ к удаленному хосту по SSH по открытому ключу.

### Шаг 1. Конфигурация хоста через Ansible
Из корня репозитория перейдите в папку `ansible/` и запустите плейбук настройки:
```bash
cd ansible
ansible-playbook -i inventory.ini setup_host.yml
```

### Шаг 2. Развертывание Docker-инфраструктуры через Terraform
Перейдите в директорию `terraform/`, выполните инициализацию и примените манифест:
```bash
cd ../terraform
terraform init
terraform apply -auto-approve
```

### Шаг 3. Запуск мультиконтейнерного стека Compose
Подключитесь к виртуальной машине под пользователем `deployer` и запустите сервисы в каталоге `/opt/app`:
```bash
ssh deployer@<VM_IP> "cd /opt/app && docker compose up -d"
```

### Шаг 4. Проверка мониторинга
Скопируйте скрипт мониторинга на хост и выполните запуск:
```bash
scp ../scripts/monitor.sh deployer@<VM_IP>:~/scripts/monitor.sh
ssh deployer@<VM_IP> "bash ~/scripts/monitor.sh docker"
```
